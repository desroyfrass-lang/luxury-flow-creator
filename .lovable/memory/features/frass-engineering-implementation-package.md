The FRASS Engineering Implementation Package (Master Implementation Directive v2.0) is one unified engineering blueprint delivered in sequential specifications.

## Delivery protocol
Do not generate code, UI, schema, AI orchestration, routing, or state decisions from these specs until the final document and the official closing implementation directive are received. Acknowledge and lock each transmission instead.

## Canonical rules (permanent)
1. Frassy is the symbolic embodiment of the FRASS Intelligence System — represented by the FrassKicks symbol, not a person, mascot, or avatar. The symbol comes alive; it never becomes human.
2. Participants are always the hero; Frassy is the guide.
3. Human intention takes precedence over software navigation — organize around what participants are building, not menus.
4. Simplicity is an engineering requirement: internal complexity inside the system, external simplicity for the participant.
5. Professional quality is the default at every skill level.

## Engineering standard
Production-grade, not prototype. Prefer scalability, maintainability, modularity, extensibility, readability, performance, accessibility, and long-term evolution over quick wins. Every capability is a modular subsystem so new assistants, academies, dashboards, creative tools, AI capabilities, workflows, partner roles, and automations can be added without redesign.

## Discipline
Never invent unspecified functionality; build extensible architecture instead of placeholder features. Where details are implied, apply senior engineering judgment consistent with FRASS philosophy.
